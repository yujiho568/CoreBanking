# 실제 사용자 인증 후 테스트베드 조회 검증

2026-11-21 사용자가 금융결제원 테스트베드 OAuth 본인인증·계좌조회 동의를 완료한 뒤 검증했다.
앞선 인증 파라미터 오류 단계에서 진전됐으며, 현재 막힌 지점은 조회 응답 데이터다.

## 성공한 범위

- CoreBanking 인증 시작과 콜백 처리.
- 실제 `/oauth/2.0/token` 인증 코드 교환.
- 실제 `/v2.0/user/me` 사용자 계좌 조회 및 로컬 외부 계좌 동기화.
- 조회에 동의한 계좌 1개가 `/api/external-accounts`에서 반환됨.
- 로컬 서버 health `UP`.

위 검증은 사용자 토큰을 사용하는 실제 테스트베드 연동이다. 토큰·계좌번호·잔액은 문서에 남기지 않는다.
DB는 격리된 로컬 H2, 캐시는 메모리 캐시다. 실제 MySQL·Redis를 사용한 통합 검증은 아니다.

## 잔액·거래내역 조회 결과

CoreBanking의 잔액·거래내역 API가 각각 금융결제원에 요청을 보냈으나 다음 업무 오류를 받았다.

```text
A0002 참가기관 에러
[API업무처리시스템 - 시뮬레이터 응답전문 존재하지 않음]
```

CoreBanking은 이를 `502 / OPEN_BANKING_PROVIDER_ERROR`로 변환했다.
잔액 강제 갱신·동일 조회·재갱신, 거래내역 강제 갱신·동일 조회의 총 5개 검증 요청이 모두 같은 오류로 실패했다.
거래내역 기간은 `2026-11-01`부터 `2026-11-21`, 최대 1페이지다.
각 요청마다 외부 HTTP 계측값이 1씩 증가했다. 따라서 실패한 응답은 캐시에 저장되지 않았다.
원인 확인을 위해 잔액·거래내역을 각 1회 추가 호출했으며 같은 오류 메시지를 확인했다.

정상 잔액·거래내역 반환, 정상 응답의 캐시 적중과 갱신 시각 비교는 아직 검증하지 못했다.
이 요청들의 지연 수치는 오류 응답 관측값이므로 정상 조회 성능 결과로 사용하지 않는다.

금융결제원 [공식 시작 안내](https://developers.kftc.or.kr/dev/starter/starter)는 API 테스트 전
서비스별 요청에 대한 응답 데이터를 사전에 등록하도록 안내한다.
개발자사이트의 테스트 정보 관리에서 연결 계좌의 잔액조회·거래내역조회 응답 데이터를 등록한 뒤 재검증해야 한다.
